# 全库概览覆盖修复（1.2.7）

## 问题和原因

“这些文献主要研究了一个什么问题”是全库主题概括，不是从全文中查找某一细节。此前两者共用全局相关度 Top-K：快速普通问题 12 段，较详细问题 20 段加少量补检；这些片段可能集中在少数论文。即使原文全部存在，送给模型的也只是其中一部分论文。快速模式又最多附带 12 篇论文的元数据，放大了概括时的信息缺口。

`fulltext_indexed_excerpts_only` 是程序给出的来源状态，而不是模型检测到原文文件缺失。旧标记还混淆了全文可读取和向量已建成，现改为准确表达“原文可用，本次仅提供摘录”。

## 数据核查

50 篇内置样例 MD 均通过随包清单的 SHA-256 校验；合计 3,282,549 字符、3,225 个片段，最短文档 16,367 字符。没有发现因缺少 MD 导致只剩 16 篇的情况。27 篇切分后有显式摘要章节；其余存在未标注摘要、PDF 布局将摘要与正文开头混排等现象。此审计不是逐页 PDF 人工对照，不能据此保证每个公式、字形和段落均无提取误差。

## 修复

- 概览意图独立路由，不把此前问答的话题自动套到整个文献库上。
- 每篇选取实质性的原文概览段，优先摘要、研究目的和前部正文。空的 Abstract 标题不能充当概览证据。
- 截取保持原文连续文本及真实偏移、页码、行号，不补写原文、不生成虚假的摘要。
- 概览包含所有已覆盖论文的元数据。提示词区分“每篇均有代表摘录”与“全文所有细节均已阅读”；引导归纳共同问题及不同子主题，不强行声称所有论文都只研究一个问题。
- 原文缺失、只有摘要、检索未覆盖、超预算遗漏分别报告。用户导入和样例共用该路径。

概览预算 42,000 字符，最多 120 篇。超过这个范围仍会受上下文预算约束，并明确报告遗漏数量；这不是无限规模分层综述系统，可按子项目或选中文献分批概括。

## 验证

- `node tests/benchmarks/overview-audit.mjs`：真实样例 50/50 覆盖，50 份论文元数据；摘录全部与原 MD 切片一致。此次约 35,688 字符，检索约 0.17 秒（仅本地检索，不含模型生成）。
- `pnpm test`：119 项通过，包括通用导入 50 篇、1500 篇预算上限、无原文、摘要回退、空摘要标题及原文偏移。
- `node tests/desktop-overview.mjs`：源码与打包程序均通过隔离桌面测试。模拟 API 验证实际发送的请求覆盖 50 篇，且只有一次回答调用，没有规划调用。
- `node tests/desktop-125.mjs`：普通事实与比较问答、索引及引用回归通过。
- 隔离环境未能复用本机加密 API 配置，因此没有获得可报告的真实 API 端到端结果。本次不声称模型回答准确率、耗时中位数或逐篇全文完整性已重新测定。

旧问答历史保持原样。安装修复版后重新提问才会使用新策略；无需删除项目或重新导入样例。
